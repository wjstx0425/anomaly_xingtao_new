# ZS32 Template v13 Manual Threshold Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the user-confirmed Template thresholds as an immutable v13 runtime bundle, restore v12 rollback integrity, and switch live defaults to v13.

**Architecture:** Snapshot the currently modified Template model into a new v13 identity before restoring v12. Reuse the existing Stage37 asset publisher, Stage34 24-group threshold publisher, and Stage37 finalizer so every model, profile, threshold, and bundle digest is regenerated by the established validation path.

**Tech Stack:** Python 3.13, uv, JSON runtime contracts, pytest, SHA256.

- Preserve `front=0.024885842800140383`, `front_left=0.029833445549011232`, and `front_secondary=0.21635736227035524`.
- Do not overwrite v12, v11, or v10 release directories.
- Keep PatchCore, YOLO, ROI, and all non-Template thresholds unchanged.
- Keep all eight views and all 24 branch groups required.
- Keep `commissioning_only=true` and `production_release_allowed=false`.
- Do not copy v12 evaluation reports as v13 evidence.
