# BMW可信OK参考图对比设计

## 目标

当BMW八视图Demo出现NG或ERROR时，操作者可通过快捷键进入参考对比模式。界面显示当前NG视角、同视角可信OK参考图和该模块证据图，帮助区分真实缺陷、反光变化、位置偏差和模型误报。参考图只用于解释，不参与四模块判定，也不改变最终OK/NG。

## 可信OK边界

候选数据只来自晚九点会话`20260810_210030_527506`，并同时满足：

- `source_class=normal`且`business_label=OK`；
- 同一物理零件八个标准视角完整，图片SHA存在；
- 排除`no_streak`、`edge`、`deform`、`others`及所有NG标签；
- 默认只从`split=train`的50个物理零件生成复核包，避免把校准集和最终测试集混入参考库；
- 人工逐零件确认后，只有明确写入不可变白名单的物理零件才能进入参考库。

清单标签只是候选条件，不能替代人工确认。在白名单尚未确认或某视角没有可信参考时，界面必须显示“无可信OK参考”，不能自动降级到未经确认的normal图。

## 方案比较与选择

1. 固定一张标准图：最简单，但不能适应正常范围内的姿态和反光差异。
2. 只在Template的五张模板中匹配：运行快，但候选范围过小，容易选到视觉差距明显的参考。
3. 在人工白名单的晚九点训练正常库中做逐视角对齐匹配：候选可信、可解释，且无需重新训练深度模型。采用此方案。

首版匹配沿用Template预处理：固定ROI、灰度化、等比例缩放、3x3高斯模糊，并在有限平移窗口内计算归一化相关系数。每个NG项目按`(视角, full或ROI比较模式)`选择相似度最高的一张可信OK图。光痕使用`front_left/full`，Template、YOLO和EfficientAD使用各视角ROI；同一`front_left`同时出现光痕与外观NG时，两份匹配必须独立保留。选择结果保留参考`physical_part_id`、`sample_id`、视角、比较模式、相似度、源图路径及SHA256。

## 数据产物

准备器生成一个不可覆盖的新版本目录：

- `candidate_manifest.csv`：50个训练normal候选、八视角路径和SHA；
- `review/contact_sheets/`：每个候选零件的八视角复核拼图；
- `review_decisions.csv`：人工填写`APPROVED`或`REJECTED`，缺省为`PENDING`；
- `trusted_ok_whitelist.json`：仅在所有入库记录明确APPROVED后发布；
- `reference_index.json`：按视角组织的可信图片、预处理身份和SHA。

白名单和索引原子发布且拒绝覆盖旧版本。索引保存源文件哈希，Demo加载时校验，避免图片被替换后仍冒充已确认OK。

## 前端交互

- `O`：开启或关闭“可信OK对比模式”；
- `N/P`：继续循环NG/ERROR项目，参考图随当前NG视角自动更新；
- 只有当前项目为NG或ERROR时，对比区域显示“现场NG / 最相似可信OK / 对齐差异 / 当前模块证据”；当前项目PASS时明确显示“当前项目通过，无需NG对比”，不得展示参考图；
- 右侧显示NG视角、NG项目、完整原因、参考零件ID和相似度；
- Template与EfficientAD明确标注为诊断热区，YOLO明确标注为真实检测框；
- 光痕参考使用同视角完整图，并保留现有光痕ROI顺时针展示。

快捷键只切换显示状态，不重新运行模型，也不改变检测结果。无检测结果、当前项目为PASS或无可信参考时给出明确中文提示。

## 现场留档

每条NG/ERROR结果继续保存原有短曝光、长曝光、HDR、ROI和证据图，并新增：

- 被选择的可信OK参考ROI副本；
- 参考源图SHA和白名单/索引SHA；
- 匹配相似度及对齐平移；
- `reference_is_diagnostic_only=true`。

历史记录由保存的参考副本和哈希复现，不依赖参考库未来仍位于原路径。

## 验证

- 单元测试覆盖候选过滤、PENDING不入库、白名单哈希校验、逐视角最近匹配、无参考时拒绝降级、快捷键切换和留档字段；
- 使用一个现场NG记录验证选图、中文布局和持久化；
- 确认开关参考对比前后25项模型结果完全一致；
- 不把参考图相似度解释为缺陷分数，也不把诊断热区解释为真实缺陷框。
