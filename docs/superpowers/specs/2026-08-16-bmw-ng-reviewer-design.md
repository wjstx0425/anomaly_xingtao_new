# BMW Template / EfficientAD NG 交互复核器设计

日期：2026-08-16

## 目标

为现有左手件 NG 整理包提供一个本地桌面程序。用户按零件浏览 Template 与 EfficientAD 报出的问题，并对每条问题独立选择“误判”“真实缺陷”或“不确定”。程序只记录人工结论，不修改检测模型、阈值、ROI 或原始检测结果。

## 方案

采用 Python Tkinter 桌面程序。它不需要启动后端服务，也不依赖浏览器的本地文件写入权限；直接读取现有 `review_cases.csv` 和 `cases/*.jpg`，并将结论原子写回 CSV。

## 交互

- 左侧按 `capture_id` 列出零件，显示已复核问题数、总问题数以及完成状态。
- 主区域显示当前零件的所有问题；每条问题显示案例编号、算法、视角、分数、阈值、原因和四联证据图。
- 每条问题独立提供“误判”“真实缺陷”“不确定”三个选择。
- 提供“将本零件剩余问题全部标为……”的批量按钮，不覆盖已经人工选择的项目。
- `1/2/3` 标记当前问题，方向键切换问题或零件，`Ctrl+S` 保存，双击证据图放大，`Esc` 关闭放大图。
- 点击选择后立即自动保存；再次启动时从 CSV 恢复进度。

## 数据合同

- 输入默认指向 `results/bmw_template_efficientad_ng_review_left_20260816_v1/review_cases.csv`。
- 必需字段包括 `case_id`、`capture_id`、`branch`、`view`、`decision`、`review_note` 和 `panel_path`。
- `decision` 仅允许空值、`误判`、`真实缺陷`、`不确定`。
- 保存前先写同目录临时文件，再替换原 CSV；列顺序及未知列保持不变。
- 不删除图片，不改 `inspection.json`，不改变算法结果。

## 错误处理

- CSV、图片或必需字段缺失时显示明确中文错误并停止，不产生半份输出。
- 单张图片无法读取时该问题显示占位提示，其余问题仍可继续复核。
- 保存失败时保留内存中的选择并提示用户重试，不伪装为已保存。

## 验证

- 单元测试覆盖分组、合法结论、批量标记不覆盖既有选择、CSV 往返保存及未知列保持。
- 使用现有 111 条案例做只读启动预检，确认得到 46 个零件、32 条 Template 问题和 79 条 EfficientAD 问题。
- GUI 启动属于现场交互验证；自动测试不启动真实窗口。
