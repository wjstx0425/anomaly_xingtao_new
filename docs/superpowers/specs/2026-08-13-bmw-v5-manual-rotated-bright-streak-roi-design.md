# BMW V5 手动倾斜光痕 ROI 设计

## 目标

V5 检测平台停止使用 `raw_profile_v2`，改用现有 `tracked_profile_v3` 光痕算法。操作员在一张现场 `front_left` HDR 原图上手动选择倾斜四边形 ROI，运行时将其透视展开为 V3 既有的 `81x613` 标准输入，并原样沿用 V3 的几何参数和判定阈值进行实验室测试。

本次现场样本 `bmw_demo_20260813_164043` 的人工真值为“有光痕但明显断续”，期望光痕结果为 `NG_BROKEN`。

## 范围

- 新增四点式倾斜 ROI 选择器：依次点击四个角，`Enter` 确认、`R` 重选、`Esc` 取消。
- ROI 资产记录四个原图坐标、源图路径和 SHA-256、标准输出尺寸及自身身份摘要；已有 ROI 和 V3 报告保持不变。
- 新增 V3 倾斜 ROI 适配层，只负责透视展开；展开后继续调用现有 tracked-profile V3 分析和分类逻辑。
- V5 配置绑定现有 V3 报告、手动 ROI 资产以及二者 SHA-256，启动时任一身份不匹配即失败关闭。
- 证据输出保留展开后的 V3 强响应、弱桥接和断点颜色，并记录原图四点坐标；界面明确显示“沿用 V3 阈值，未针对新 ROI 重标定”。

不修改 Template、YOLO、EfficientAD、八视角公共裁剪、HDR 参数或最终融合逻辑。

## 数据流

1. 选择器读取 `bmw_demo_20260813_164043/images/front_left_hdr.png`。
2. 操作员按顺时针顺序点击四角，选择器预览四边形和 `81x613` 展开图。
3. 确认后发布不可覆盖的 ROI JSON 资产。
4. V5 启动时校验 V3 报告和 ROI 资产的 SHA-256。
5. 光痕分支从未经过 Template 对齐的现场 `front_left` 融合 HDR 原图截取倾斜区域并透视展开。
6. 展开图进入现有 V3 路径追踪、强弱阈值、覆盖率、最长连续段、最大断点和断点数判定。

## 约束与失败处理

- 四个点必须形成凸四边形，且全部位于 `4024x3036` 原图范围内。
- 点击顺序固定为左上、右上、右下、左下；预览不正确时必须重选。
- 本轮不重新拟合阈值，因此只称为实验室候选测试，不声称完成新 ROI 标定。
- ROI 缺失、退化、顺序错误、源图 SHA 不匹配、配置 SHA 不匹配或透视展开失败时，光痕分支返回错误并使整件失败关闭。
- 旧 `tracked_profile_v3` 固定 ROI 路径继续可用，作为回退基线。

## 验证

- 单元测试覆盖四点校验、透视展开尺寸/方向、V3 参数复用、配置 SHA 失败关闭以及非光痕分支不变。
- 用 `bmw_demo_20260813_164043` 离线重放；光痕必须返回 `NG_BROKEN` 才算达到本次样本目标。
- 对既有正常、无光痕样本做少量回归，记录结果但不据此重新选择阈值。
- 核对 V5 仍输出原有 25 个分支结果，除光痕证据与状态外其余 24 项不因本次改动发生语义变化。
