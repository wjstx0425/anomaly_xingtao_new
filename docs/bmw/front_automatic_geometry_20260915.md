# BMW front：自动匹配、几何关系与当前轮廓采集

## 目标与实现

用户希望用稳定孔和直边建立坐标系，使待测图自动匹配，并优先获得零件轮廓。依据 `/home/yunjing/MVI_xingtao_PL/V/兴韬_BMW整圈轮廓提取与自动定位_算法方案汇总_V1.md` 第4、5节，新增独立离线路径，保留旧严格轮廓比较。

| 特征 | 本轮用途 | 限制 |
| --- | --- | --- |
| 两孔椭圆拟合中心 H1/H2 | 自动寻找唯一孔对，建立二维刚性坐标系 | 不允许缩放或非刚性对齐；不能单独证明无3D姿态变化 |
| 孔间距 | 检查孔对身份、投影几何是否相容 | 不因定位拟合而宣布孔位置度合格 |
| 上孔旁主体外直边 E1 | 不参与定位拟合的独立校验 | 目前是开发选段，物理基准尚未确认 |
| 中部右侧直边段 E2 | 孔到线距离、方向变化诊断 | 大偏差可能是错边、投影或形变，需要实图复核 |
| 上下小脚端边 F1/F2 | 最近孔到端边拟合直线的垂直距离 | 小脚不参与定位，形变不能被拟合消掉 |
| 直线支撑跨度、拟合残差 | 衡量可见线段与直线假设质量 | 仅为采样区间支撑长度，不是含圆角的完整实物边长 |

所有距离为原图像素投影距离。孔中心到无限拟合直线的垂足可能落在采样段外，JSON明确标注；不能误称为孔到有限线段最短距离、毫米尺寸或三维点到面距离。

## 自动匹配

原实现只在固定两孔ROI中提椭圆。本轮可选 `registration.coarse_search` 使用原大小窗口在扩大范围扫描，局部 Otsu + `cv2.fitEllipse` 提候选；聚类去除同一孔的重复观测，再按轴长、孔间距、旋转和平移范围保留唯一孔对。随后平移原ROI重新精拟合，最后仅求SE(2)刚性变换。

若缺孔、合理候选不唯一、孔间距变化或运动超限，返回无效位姿及原因，不回退单位矩阵。默认配置未启用新增搜索，旧调用保持原行为。新开发配置为 `configs/bmw/checks/contour/left_front_4024_automatic_geometry_v1.json`，搜索边距250px，位移上限250px、角度上限6°，这些是开发搜索限制，非现场验收参数。

局部直边沿位姿变换后的卡尺在原图采样，当前材料mask判断内外方向，再选唯一同极性梯度。不能仅凭最强梯度选择更亮的工装边。用 `cv2.fitLine(DIST_HUBER)` 拟合原始观测，并保留全部残差和未知点，不将拟合直线替代轮廓。

成熟算法说明：[OpenCV 椭圆和直线拟合](https://docs.opencv.org/4.13.0/d3/dc0/group__imgproc__shape.html)。

## 轮廓采集与严格比较的区别

- `acquisition.py` 从当前 GrabCut 分割的密集外边界出发，保存全部候选，不经过凸包或轮廓平滑。
- 在当前mask局部内法向±3px找真实梯度；无对比度、歧义、尖角、透明/越界区域保留未知。
- CSV同时含 `candidate_x/y`、`observed_x/y`、`valid`、`reason`、`next_index`、`segment_valid`。只有 `segment_valid` 对应的相邻点可作为实测线连接。
- mask仍由参考作可改变概率初始化。分割候选的材料语义没有全部确认，完整闭合不等于全部正确。
- 图像支持比例分母为**当前分割候选弧长**；旧72–89%指标分母为**固定参考必检弧长**，二者不能当成同一种覆盖率比较。
- 旧严格比较还要求参考校准与角点对应。诊断发现固定参考708角点未知、239校准未知、49法向未知；简单合并碎片角点未带来实图提升，实验已撤回。

## 实测与验证

本轮仍处理原8张左件/front、4024×3036历史开发图，不是全量423张，也不是独立验收集。输入清单来自 `artifacts/bmw_front_contour_20260915/manifest.json`。

- 八张原图双孔定位均成功。
- 对真实参考图数字旋转±4°并平移±80px，以及水平120px、竖直-100px：旧固定窗口4例均失败，新定位4例均成功；相对已知数字变换的最大孔中心误差不超过0.077px。这是数字扰动测试，不是实物重复取放精度。
- 全部轮廓相关测试223项通过，有既有NVML警告；没有GPU/相机/生产节拍验证。
- 最终入口：`artifacts/bmw_front_automatic_geometry_20260915/review.html`，包含原分辨率图、mask、坐标CSV/NPZ、几何JSON和未检边证据。最终几何结果在 `final/*/geometry.json`。
- 早期 `geometry_v1/v2/v3` 为开发诊断，`acquisition_v1` 保存实际采集mask/轮廓；最终报告将线距离基线统一为自动分割的参考，与当前图采用相同身份判据。没有改动当前图原始线观测、孔位姿或轮廓数组。不要以早期几何汇总作为最终结果。

## 复现

从仓库根目录执行，输出目录必须不存在：

```bash
UV_CACHE_DIR=/tmp/bmw-uv-cache uv run --no-sync python tools/bmw/measure_front_geometry.py \
  --manifest artifacts/bmw_front_contour_20260915/manifest.json \
  --config configs/bmw/checks/contour/left_front_4024_automatic_geometry_v1.json \
  --reference-mask artifacts/bmw_contour_reference_20260912/reference_mask_folds_only.png \
  --acquire-contour --output-dir artifacts/bmw_front_automatic_geometry_replay
```

当前脚本对参考和待测均先自动分割再测直线，因此复现直接使用相同基线，无需事后修正。`geometry_validation` 仍是未确认的开发一致性阈值；全流程结果固定REVIEW，不替代旧放行规则。

## 最终实图复核与剩余问题

- 最终参考两孔中心间距1662.91px；H1到E1为170.88px，H1到F1为478.51px，H2到F2为486.29px。均为本图投影测量，不是图纸名义尺寸。
- normal001：E1距离变化-0.11px、上脚变化+0.01px、下脚变化-4.78px。该件已被用户确认正常，不能仅凭下脚变化宣布缺陷，也不能据一件正常图确定生产公差。
- 每图保存8605–10953个密集候选顶点。当前候选的图像梯度支持比例41.3%–60.8%，这不是旧固定参考覆盖率，更不是准确率。
- 查看八图总览后确认：normal001/003及缺陷图的下部左暗面存在GrabCut误分割，向材料内部产生假凹口；部分小脚折痕仍成为错误候选边。完整候选因此不能作为已确认材料外轮廓。当前自动匹配已打通，可靠整圈提取尚未完成，后续工作应针对暗材料/背景归属，而不是通过稳定基准强行补名义边。
- `report.py`核验8图SHA、尺寸、刚性矩阵、CSV/数组一致性、未知不桥接，并断言统一自动参考基线后的自身线距离差为零。报告生成成功；最终脚本另做一次参考图端到端检查。
